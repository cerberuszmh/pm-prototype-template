## 3. 编写目的

- **本文档目标**：明确示例记录管理模块的业务目标、范围、角色、流程及业务验收口径。
- **本模块需求解决的问题**：
  1. 记录管理员需要快速定位目标记录。
  2. 记录管理员需要在统一入口完成记录创建、编辑和状态维护。
  3. 模板学习者需要理解业务需求与技术规格的分工。
- **面向的评审对象**：产品负责人、业务评审人、开发与测试人员。

## 4. 需求背景

- **模块业务背景**：现有模板只有空文档骨架，缺少一套能与页面行为相互对照的模块成品。
- **当前痛点**：使用者容易把字段类型、校验和精确提示文案写进 PRD，造成 PRD 与 SRS 重复维护。
- **触发原因**：需要通过一个最小记录管理场景展示业务文档、技术规格和原型之间的正确关系。
- **相关系统/模块**：项目级约束见 P07 §9～§12；本样例无其他业务模块依赖。

## 5. 模块目标

- **模块业务目标**：让记录管理员能够完成示例记录的查询、创建、编辑和状态管理。
- **用户目标**：在一个列表页面内完成高频记录维护，不依赖多个页面来回跳转。
- **成功指标**：首次接触模板的 PM 能根据本样例区分 PRD 与 SRS 的内容归属，并完成同结构文档。

## 6. 范围说明

### 6.1 本模块范围

- 按记录名称和状态查询。
- 新建示例记录。
- 编辑示例记录的名称和状态。
- 查看状态并执行允许的状态切换。
- 对不可逆归档操作进行二次确认。

### 6.2 非本模块范围

- 登录、组织与角色配置。
- 删除、批量处理、导入和导出。
- 真实后端接口、数据库与部署。

## 7. 角色与用户

| 角色 | 场景描述 | 核心诉求 |
| --- | --- | --- |
| 记录管理员 | 日常维护示例记录 | 快速找到记录并完成创建、编辑和状态调整 |
| 业务评审人 | 核对页面是否符合业务规则 | 确认流程、术语和反馈语义一致 |

> 全局角色与权限模型见 P07 §2、§5；详细权限矩阵见 SRS §7。

## 8. 业务流程概述

### 8.1 主流程

1. 记录管理员进入“示例列表”页面。
2. 记录管理员输入名称或选择状态，点击“查询”。
3. 系统展示符合条件的记录，并保持创建时间较新的记录在前。
4. 记录管理员可新建记录或编辑已有记录。
5. 记录管理员可通过状态标签选择新的状态；归档操作确认后生效。

### 8.2 异常流程

| 业务异常场景 | 业务侧处理建议 |
| --- | --- |
| 新建或编辑时必填信息不完整 | 阻止保存，并提示用户补充必要信息 |
| 用户误触归档 | 在执行前展示二次确认，允许取消 |
| 查询无匹配记录 | 展示空结果，不改变已输入的查询条件 |

> 详细技术异常处置及提示文案见 SRS §5.2.5、§5.3.5。

## 9. 功能需求明细

### 9.1 示例记录查询

#### 9.1.1 业务目标

- **解决问题**：帮助记录管理员从列表中快速定位目标记录。
- **目标角色**：记录管理员、业务评审人。
- **使用场景**：按名称模糊查找，或按状态精确筛选。

#### 9.1.2 业务功能与字段

| 字段名 | 业务用途 |
| --- | --- |
| 名称 | 识别记录并作为查询条件 |
| 状态 | 判断记录所处业务阶段并作为查询条件 |
| 创建时间 | 判断记录新旧顺序 |

> **完整字段规格**：见 SRS §5.1.2 页面与字段。

#### 9.1.3 业务规则

- 输入筛选条件不会立即改变结果，点击“查询”后统一应用。
- 点击“重置”后清空筛选条件并恢复全部记录。
- 默认按创建时间从新到旧展示。

#### 9.1.4 业务侧关键交互

| 业务操作 | 业务侧期望反馈 |
| --- | --- |
| 点击查询 | 展示符合当前条件的记录 |
| 点击重置 | 清空条件并恢复全量列表 |

> **完整交互规格**：见 SRS §5.1.3 处理逻辑。

### 9.2 示例记录维护

#### 9.2.1 业务目标

- **解决问题**：在统一入口完成记录创建和编辑。
- **目标角色**：记录管理员。
- **使用场景**：创建新记录或修正已有记录信息。

#### 9.2.2 业务功能与字段

| 字段名 | 业务用途 |
| --- | --- |
| 编号 | 唯一识别一条示例记录 |
| 名称 | 描述记录的业务名称 |
| 状态 | 表示记录当前业务阶段 |
| 创建时间 | 记录创建时点并支持默认排序 |

> **完整字段规格与校验规则**：见 SRS §5.2.2 页面与字段。

#### 9.2.3 业务规则

- 新建记录时由系统生成编号和创建时间。
- 新建记录的默认状态为“草稿”。
- 编辑记录时允许修改名称和状态。

#### 9.2.4 业务侧关键交互

| 业务操作 | 业务侧期望反馈 |
| --- | --- |
| 保存有效记录 | 告知用户保存结果并关闭编辑窗口 |
| 保存信息不完整的记录 | 阻止保存并引导用户修正 |

> **完整交互与反馈细节**：见 SRS §5.2.3、§5.2.5。

### 9.3 示例记录状态管理

#### 9.3.1 业务目标

- **解决问题**：让管理员直观看到并维护记录所处阶段。
- **目标角色**：记录管理员。
- **使用场景**：从状态标签进入状态切换操作。

#### 9.3.2 业务功能与字段

| 字段名 | 业务用途 |
| --- | --- |
| 状态 | 展示记录当前阶段，并作为状态切换入口 |

> **完整状态规格**：见 SRS §5.3.2、§5.3.4。

#### 9.3.3 业务规则

- 可选目标状态不重复展示当前状态。
- 归档属于不可逆操作，确认后不能再次切换。
- 非归档状态切换确认选择后直接生效。

#### 9.3.4 业务侧关键交互

| 业务操作 | 业务侧期望反馈 |
| --- | --- |
| 点击状态标签 | 展示可切换的其他状态 |
| 选择归档 | 要求再次确认后执行 |
| 完成状态切换 | 明确告知切换结果 |

> **完整状态机和提示文案**：见 SRS §5.3.3～§5.3.5。

## 10. 业务级非功能要求（模块特有）

- **业务侧响应预期**：用户执行查询或状态切换后应立即得到明确结果。
- **业务侧权限边界**：仅记录管理员可以创建、编辑和切换状态。
- **业务侧日志与审计要求**：本教学原型不落真实审计日志，正式项目应由项目级要求决定。
