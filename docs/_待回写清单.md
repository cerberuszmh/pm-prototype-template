# 待回写清单（活动清单）

> 已回写和已取消记录按年度移入 `docs/archive/待回写记录-{YYYY}.md`，归档文件只用于追溯，不得维护待办。

## 使用规则

| 时机 | AI 动作 |
|---|---|
| 原型改动通过登记准入 | 使用“下一个编号”新增 `⏳ 待回写`条目，并同步推进两个编号水位 |
| 同一锚点仅发生细化 | 更新原条目摘要，不新增编号 |
| 用户触发回写窗口 | 先处理本文件全部 `⏳`条目，再继续执行被触发流程 |
| 条目完成或确认无需回写 | 将 `✅ 已回写`或 `❌ 取消回写`记录追加到当年归档，随后从本文件移除 |
| 条目暂时搁置 | 标记为 `🟡 已推迟`，并记录原因和重启条件，继续保留在本文件 |
| `⏳`条目数达到 10 | 主动提示建议提前安排回写窗口 |

## 编号约定

- 编号格式为 `RB-{nnn}`，全项目唯一且永久不复用。
- 新增条目前同时核对本文件编号水位与当年归档最高编号。
- 归档操作不得回退“最新已用编号”或“下一个编号”。
