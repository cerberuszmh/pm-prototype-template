# 开发交接

## 上下游 SKILL（工作流定位）

本 SKILL 在项目工作流中处于**原型评审通过 → PM 责任终点**之间，专门把 PRD/SRS/原型重新组织为开发友好交付物。

| 上游 | 本 SKILL | 下游 |
|------|---------|------|
| `评审` 阶段 2（原型评审业务决策已通过） | **开发交接**（数据字典 + PM 开发交接包） | PM 责任终点；交付程序员后由程序员决定其后续流程 |

**典型工作流**：

```
原型评审通过 → 开发交接【5 项强制 + 1 项可选；原型代码包依赖闭合】→ PM 交付完成
```

## 核心原则

1. **必须先通过原型评审**：原型评审未通过则**拒绝执行**，引导用户先回到 `评审` SKILL 阶段 2；不得跳步生成开发包。
2. **强制项的两个层级**（不可混淆）：
   - ① **本 SKILL 必须新生成的项** = **数据字典**（1 个）；
   - ② **开发交接强制五项** = **PRD / SRS / 数据字典 / 原型代码包 / 原型评审结论**，任一缺失则本 SKILL 拒绝执行；
   - **流程图**为可选项（如有则纳入交付包，缺失不阻断）；
   - 其他增项（接口契约 / 测试用例 / Cursor 规则包 / 错误码矩阵 / Mock 数据规范 / 决策日志）仅在用户明确勾选时生成。
3. **数据字典是派生文档，不引入新规则**：字段定义、必填、校验规则的唯一权威源是 SRS §5。本 SKILL 只做"扁平化提取 + 命名映射"，禁止在数据字典内增补 SRS 没有的业务规则。**例外**：将 SRS 中标注"待确认"的字段在数据字典中**透传**该标注（不做实质性补全），不算引入新规则。
4. **冲突即停**：发现 SRS、PRD、mock 实现三者不一致时，立即停止并向用户报告，由用户决定以哪个为准；不得自动选择。
5. **不修改 SRS / PRD / 原型代码（含其中的 mock 数据）**：本 SKILL 是"读取 + 派生"，禁止修改任何上游文档与代码。
6. **检查点强制停止**：本 SKILL 输出完成后输出"🛑 已停止"检查点，是否立即把开发包移交程序员进入接口对齐，由用户在新一轮对话中确认。
7. **生产构建不属于 PM 门槛**：PM 完成原型评审与本 SKILL 的开发包校验后即可交付程序员；`npm run build`、接口联调、数据库和部署由程序员接手后执行，不得因生产构建未验证阻断 PM 交付。

## 触发条件（强制）

进入本 SKILL 前必须确认以下 5 项，缺一不可（覆盖开发交接强制五项中除待生成数据字典外的 4 项 + 用户触发意图）：

| 检查项 | 必须满足 | 不满足时的处理 |
|---|---|---|
| PRD 已存在 | `docs/formal-requirements/M{n}-02-{模块名}模块产品需求文档（PRD）.md` 存在 | 拒绝执行，引导回 `项目与模块启动` SKILL §2.4 |
| SRS 已存在 | `docs/formal-requirements/M{n}-03-{模块名}模块软件需求规格说明书（SRS）.md` 存在且 §5 字段表完整 | 拒绝执行，引导回 `项目与模块启动` SKILL §2.5 |
| 原型代码包已存在 | `src/views/{模块目录}/**/*.vue` 至少 1 个文件存在；其余依赖按 §2.0.1 发现并纳入 | 页面缺失则拒绝执行，引导回 `项目与模块启动` SKILL §2.7 |
| 原型评审通过 | `docs/review/{模块名}原型评审结论.md` 存在，且满足以下二者之一：① 报告 §5.1 决策表"用户最终决策"列含"通过/是"等明确决策值；② 报告末尾追加了"评审正式关闭"声明（按 `评审` SKILL 阶段 2 §6.1 第 7 项要求）。二者均不满足时视为未通过 | 拒绝执行，引导回 `评审` SKILL 阶段 2 |
| 用户明确触发 | 用户主动说"开发交接""数据字典""开发包""给程序员"等明确意图 | 不主动触发，等待用户明示 |

> **说明**：上表前 4 项即为完整交付包前 5 项强制项中除"数据字典"以外的 4 项（数据字典由本 SKILL 在 §第三步生成），合在一起构成"前 5 项强制项全部存在"的硬性前置条件。

若用户已在上下文中明示，则不重复追问。

> **按需增项的勾选**统一在 §第四步检查点询问，第一步不重复问，避免与检查点 C 选项割裂。

### 2.0.1 原型代码包依赖发现（存在则纳入）

以 `vue-ui-implementation.mdc §"Mock 组织与发现协议"` 为权威源，执行以下校验：

| 类别 | 路径或检索方式 | 交接处理 |
|---|---|---|
| 页面组件 | `src/views/{模块目录}/**/*.vue` | 强制，至少 1 个；缺失即停止 |
| 独立 Mock | 扁平文件或可选嵌套目录 | 命中则列入；未命中继续检查内联 Mock |
| 内联 Mock | 模块页面中的具名 `reactive` / `ref` 数据 | 命中则记录文件与变量名 |
| 共享枚举 | 页面实际引用的 `src/mock/enums.js` export | 只列实际引用项 |
| 路由注册 | `src/router/index.js` 中匹配本模块的路由与 meta | 存在则列入；纯弹窗模块可标 N/A |
| 菜单注册 | `src/layouts/WorkspaceLayout.vue` 中匹配本模块的菜单项 | 存在则列入；无菜单入口可标 N/A |
| 复用逻辑 | 页面实际 import 的 `src/composables/*` | 存在则列入 |

未命中的可选依赖必须标注 `N/A + 原因`，不得把“未发现”写成“已交付”；系统共享骨架不重复计入模块强制项。

## 第三步：执行（数据字典生成）

0. **开发交接强制五项存在性校验**（执行前的硬性 stop 检查）：
   - 用 `Glob` 或 `Read` 验证以下 4 个文件存在（数据字典是本步骤将要生成的，第 3 项暂不在此校验）：
     - `docs/formal-requirements/M{n}-02-{模块名}模块产品需求文档（PRD）.md`
     - `docs/formal-requirements/M{n}-03-{模块名}模块软件需求规格说明书（SRS）.md`
     - `src/views/{模块目录}/**/*.vue` 至少 1 个文件
     - `docs/review/{模块名}原型评审结论.md`
   - **同时校验"原型评审通过"**（仅文件存在不充分）：用 `Read` 读评审结论文件，确认满足以下二者之一（与 §触发条件表第 4 行判定一致）：
     - ① §5.1 决策表"用户最终决策"列含"通过 / 是"等明确决策值；
     - ② 报告末尾追加了"评审正式关闭"声明。
   - 任一缺失：立即停止，输出"❌ 强制项缺失：{产出物名称}"或"❌ 原型评审未通过（决策表与关闭声明均未满足）"并按 §触发条件表格"不满足时的处理"列引导回对应 SKILL；不进入数据字典生成。
   - 全部存在且评审通过：继续执行下面 1~6 步。
0.5. **原型代码包依赖发现**：
   - 按 §2.0.1 与 `vue-ui-implementation.mdc §"Mock 组织与发现协议"` 检查 Mock、共享枚举、路由、菜单和 composable。
   - 输出"命中路径 / N/A + 原因"清单；该清单既用于字段冲突核查，也随开发交接包移交。
1. **读取依据**：从 SRS §5 提取所有字段、状态、枚举，从 PRD 同步元信息（版本、维护人）。
2. **采用模板**：以 `templates/data/data-dictionary-template.md` 为起点，不得从空白开始。
3. **聚合规则**：
   - 字段表按 SRS §5.x.2 的分区聚合（如：基础信息 / 联系信息 / 业务信息 / 状态信息 / 其他信息，按本项目实际分区为准），重复字段去重
   - 列表特有字段、派生显示字段单独成节
   - 状态机字典聚合 SRS §5.x.4 中所有状态字段
   - 枚举字典聚合 SRS §5.x.2 中所有 a-select 字段
4. **命名映射**：前端字段名取自现有 mock 实现（保持一致），后端字段名给出 snake_case 建议
5. **冲突标注**：以下 3 类**硬性冲突**任一发生立即停止并向用户报告，由用户决定以哪个为准：
   - **字段缺失**：SRS §5.x.2 列出但 mock 未提供（或反之）
   - **类型不符**：SRS 规定 `number` 但 mock 给 `string`、SRS 规定 `array` 但 mock 给 `string` 等
   - **枚举值不符**：SRS 规定枚举范围 X/Y/Z 但 mock 中出现 W
   非阻断的差异（如 mock 字段顺序与 SRS 不同、mock 字段比 SRS 多一个非业务字段）**不停止**，仅在数据字典 §6 变更摘要中如实标注。
6. **输出文件**：写入 `docs/data/{模块名}数据字典.md`

## 第五步：移交

根据用户选择：

- 选 A → 明确告知"PM 开发交接已完成，开发包位于 `docs/data/`；后续接口对齐与构建验证由程序员主责"，再移交 `接口对齐` SKILL

## 产出自检（本 SKILL 专用）

每次完成本 SKILL 后，**先自检以下 8 项产出质量**：

1. 是否仅产出用户勾选的输出物，没有超纲？
2. 数据字典是否仅来自 SRS §5，没有自创业务规则？
3. 字段总数是否与 SRS §5.x.2 各分区聚合后的去重总数一致？
4. 状态机字典是否覆盖 SRS §5.x.4 全部状态字段？
5. 枚举字典是否覆盖 SRS §5.x.2 全部 a-select 字段？
6. 是否未修改任何上游文档（SRS/PRD/原型代码含 mock 数据）？
7. 原型代码包是否列出 Mock、共享枚举、路由、菜单、composable 的命中路径或 `N/A + 原因`？
8. 是否在末尾输出"🛑 已停止"检查点，未自行进入下一阶段？

> 上述 8 项为本 SKILL **产出物质量自检清单**，与下文"答复忠实执行核查"为不同概念，不可混淆。

## 答复忠实执行核查（引用通用规则）

本 SKILL §第四步检查点接收用户 A/B/C 选择（含"按需增项 6 项"勾选），用户选择本身即"答复"。**移交方向必须与用户答复一致**。

按 `.cursor/rules/answer-faithfulness.mdc` 执行：

- **适用步骤**：步骤 3（解析答复方向）→ 步骤 4（核查改动方向）→ 步骤 5（偏差报告）
- **不适用步骤**：步骤 1~2（无报告需读取）、步骤 6（无报告需追加标识）、步骤 7（无报告状态需回写）

> 本 SKILL 不产出含"问题清单/答复列"的报告，因此不涉及通用规则的报告回写场景；但移交动作必须忠实于用户在 §第四步的 A/B/C 选择。
