# 文档生成与版本管理

## 上下游 SKILL（工作流定位）

本 SKILL 在项目工作流中处于**文档产出与维护**节点，可在多种场景下触发。

| 上游 | 本 SKILL | 下游 |
|------|---------|------|
| `项目与模块启动`（推进各阶段触发文档生成）/ `需求变更`（变更后触发文档升版） | **文档生成与版本管理** | `评审`（阶段 1 文档层 QA 核查）/ `交付检查`（多文档交付前做一致性检查） |

**典型工作流**：

```
项目与模块启动 阶段 N → 文档生成与版本管理（生成对应文档）→ `评审` SKILL 阶段 1（文档层 QA）→ 用户决策是否继续推进
```

### 项目验收文档排除边界

- 本 SKILL 不生成或维护 A01 需求规格说明书、A02 概要设计说明书、A03 详细设计说明书。
- 用户提出项目验收文档诉求时，本 SKILL 必须停止，不得调用、路由、跳转或串联执行 `项目验收文档`；只能提示用户另行使用验收技能定义的专用手动命令。
- 用户仅说“生成 SRS”时，仍按模块级 SRS 路由；不得据此推断用户需要 A01。
- 未通过验收专用手动命令显式触发时，不得因“验收”“正式交付”或“说明书”等宽泛措辞自动生成 A 系列文档。

---

## 核心原则

1. 优先区分"新生成 / 补充更新 / 版本升级"三类任务，对号入座（详见 §第一步）。
2. 阶段约束以 `项目与模块启动` SKILL §核心原则为权威源，本 SKILL 不重复定义。
3. 生成时优先选择对应模板；补充时优先保留现有文档结构与术语。
4. 升版时只升有实质性内容变更的文档；无改动不升版。
5. 不确定信息统一标注"待确认"，不擅自编造业务事实；未经用户要求不默认顺带生成整套文档。
6. A01～A03 项目验收文档不属于本 SKILL 的新生成、补充更新或版本升级范围。

---

## 第一步：判断任务类型

| 类型 | 特征描述 | 跳转 |
| --- | --- | --- |
| 新生成文档 | 当前还没有该文档，需要从输入材料生成正式草稿 | → 第二步 |
| 补充/更新文档 | 已有文档，需要补章节、补规则、补范围、补验收标准 | → 第三步 |
| 版本升级 | 文档内容已变更，需要升版本号、生成版本记录、同步跨文档引用 | → 第四步 |

若目标不清晰，追问：要生成哪一类文档 / 是从零生成还是补充 / 当前已有的输入材料 / 本轮处理范围。

## 第二步：按文档类型路由（新生成）

> **生成规则的权威源**：所有文档生成的具体要求由 SKILL（本 SKILL 或对应专项 SKILL）+ Template + 规则文件三层共同承担，按"单一权威源"原则维护。

### 路由表（指针型文档类型）

下列文档类型由其他 SKILL 或规则文件作为权威源，本 SKILL 仅做路由：

| 文档类型 | 模板 | 权威源（生成约束详见此处） |
|---|---|---|
| 结构化需求底稿（**已废弃，仅维护老模块既有文件**） | `templates/requirements/structured-requirements-template.md` | 禁止为新模块生成；现行模块走 `项目与模块启动` SKILL §2.4 二件套 |
| 项目对齐稿（**已合并入项目级 PRD，仅维护历史文件**） | `templates/requirements/project-alignment-template.md` | 禁止为新项目生成；现行对齐决策写入 P07 §9~§12 |
| PRD（模块级二件套核心入口） | `templates/requirements/module-prd-template.md` | `doc-format.mdc §"PRD / SRS 分工边界"` + `项目与模块启动` SKILL §2.4（新模块 PRD 必须含 §需求背景 + §待确认清单） |
| SRS | `templates/requirements/srs-template.md` | `doc-format.mdc §"PRD / SRS 分工边界"` + §"SRS 文档统一规范" |
| 流程说明 / 流程图 | `templates/design/business-flow-template.md` | `doc-format.mdc §流程图` |
| 页面原型评审结论 | `templates/review/prototype-review-decision-template.md` | `评审` SKILL 阶段 2（**禁止**绕过）|
| 需求变更说明 | `templates/requirements/requirement-change-template.md` | `需求变更` SKILL（**禁止**绕过）|

**输入参考**：各路由所需输入由对应 SKILL 执行时向用户追问收集，无需独立输入模板。

### 测试用例（本 SKILL 直接承载）

- 模板：`templates/testing/test-cases-template.md`
- 适用：已有需求文档、流程图或原型，需要形成测试覆盖
- **生成强制约束**：
  - 覆盖 5 维度：主流程 / 异常流程 / 权限控制 / 边界输入 / 回归关注点
  - 用例步骤可执行；预期结果可验证，禁止使用模糊词
  - 按测试优先级 **TC-P1 / TC-P2 / TC-P3** 分级（与 `评审` SKILL 阶段 1 严格审查的"问题严重度 P1/P2/P3"区分，不可混用）
  - 每条用例须含"关联 SRS-AC"列引用对应技术 AC 编号（如 SRS-AC-12）
  - 预期结果中的 Toast 文案须与 SRS §5.X.5 异常处理表 + `vue-ui-implementation.mdc §"Toast 文案规范"` 完全一致

### 使用说明书（本 SKILL 直接承载）

- 模板：`templates/manuals/user-manual-template.md`
- 适用：已有页面原型、流程与角色说明，需要形成操作说明
- **生成强制约束**：
  - 操作步骤须**段落形式**逐步描述，**禁止**用表格描述步骤
  - 截图须**单独成段**展示，含图号 + 图名 + 一句话说明，每张图只说明一个重点
  - 关键步骤在正文中用图号引用（例如"参见图 5-1"）
  - 涉及手机号、客户信息等敏感数据时**必须脱敏**
  - 系统反馈文案须与 SRS §5.X 与 `vue-ui-implementation.mdc §"Toast 文案规范"` 一致，**禁止**改写

> **评审问题清单已废弃**：与 `评审` SKILL 阶段 1（严格审查）输出的 P1/P2/P3 问题清单同质化。如需评审问题清单，**直接触发 `评审` SKILL（默认进入阶段 1）**。

## 第三步：补充或更新现有文档

当用户说"补充""完善""更新""修订"时：

1. 先读取现有文档，保留章节结构、版本记录和术语口径。
2. 只补用户关心的章节或直接相关缺口；若用户只说"补某份文档"，不自动扩展为全链路交付。
3. 若发现与其他交付物不一致，优先指出差异，再按用户要求修订。
4. 重点保留：现有标题层级、角色/状态/字段名称、已确认范围、已有版本记录。

---

## 第四步：版本升级

### 4.1 判断哪些文档需要升版

**先读当前版本号，避免重复升版**：

1. 读取每份文档信息表中的 `文档版本` 字段，记录当前版本；项目级 PRD 的文档信息为不编号前置块，模块级 PRD/SRS 的文档信息为 §1。
2. 读取版本记录表最新一条，确认日期与本次变更日期是否相同；项目级 PRD 的版本记录为不编号前置块，模块级 PRD/SRS 为 §2。
3. 若最新版本记录日期等于今天 **且** 修改说明与本次变更内容高度重叠，视为已升版，**不重复升版**，仅在版本记录中追加说明。

遍历核心交付文档（实际文件名以项目 PRD/SRS 为准）：

| 文档 | 路径 | 当前版本字段位置 |
| --- | --- | --- |
| 项目级 PRD | `docs/formal-requirements/P07-{系统名}产品需求文档（PRD）.md` | `文档信息（不编号前置块）→ 文档版本` |
| 各模块 PRD | `docs/formal-requirements/M{n}-02-{模块名}模块产品需求文档（PRD）.md` | `§1 文档信息 → 文档版本` |
| 各模块 SRS | `docs/formal-requirements/M{n}-03-{模块名}模块软件需求规格说明书（SRS）.md` | `§1 文档信息 → 文档版本` |

**升版判定标准**（按可验证的变更事实判断）：

| 变更类型 | 可验证特征 | 升级幅度 |
| --- | --- | --- |
| 新增或删除功能点/页面 | §5 下新增或删除了 `### 5.x` 节 | minor（如 V0.8 → V0.9） |
| 字段、状态、验收标准修订 | §5 字段表、§10 验收标准表中的行内容有变动 | patch（如 V1.0 → V1.1） |
| 文档结构重组、模块范围变更 | §1/§3 范围边界或章节层级有结构性调整 | major（如 V0.x → V1.0） |
| 错别字修正、格式整理 | 无实质规则/字段/范围变动 | 不升版，版本记录注明 |

**未发生实质性变更的文档不得强制升版。**

### 4.2 生成版本记录条目

每条版本记录条目格式：

```markdown
| V{版本号} | {YYYY-MM-DD} | {修改人} | {变更摘要，按章节列出主要改动} |
```

变更摘要写作规范详见 `.cursor/rules/doc-format.mdc §"SRS 文档统一规范"下的版本记录规范`（含条目上限 3~5 条、合并前缀格式、禁用模糊动词、禁止内部审查编号等）。

### 4.3 同步跨文档版本引用

升版后检查以下引用关系是否同步：

- PRD `§1 文档信息 → 对应 SRS` 引用版本是否更新
- SRS `§1 文档信息 → 对应 PRD` 引用版本是否更新
- 如版本引用不同步，在输出中明确提示需更新的位置。

### 4.4 输出格式

升版完成后，输出一张汇总表：

| 文档 | 升版前 | 升版后 | 变更摘要 |
| --- | --- | --- | --- |
| PRD | V0.8 | V0.9 | §3 新增"XX管理"范围说明 |
| XX模块 SRS | V1.1 | — | 无实质性变更，不升版 |
| YY模块 SRS | V0.8 | V0.9 | §5.1 状态机规则补全 |

---

## 第五步：用户决策后的执行核查（强制）

用户对"升版范围 / 跨文档引用同步范围 / 不升版的判定"等决策给出答复后，按 `.cursor/rules/answer-faithfulness.mdc` 全流程执行：
- 读取本轮升版后的各文档 §2 版本记录 → 提取答复 → 解析方向 → 核查改动 → 偏差报告 → 追加核查标识 → 状态回写。
- **本 SKILL 特定回写**：在 §4.4 升版汇总表中明确标注"已升版/未升版（理由）"，禁止保留"待定"等中间态。
- 涉及跨文档引用同步（PRD ↔ SRS）时，必须 `Grep` 验证 `§1 文档信息 → 对应 SRS/PRD` 引用版本号已同步。
