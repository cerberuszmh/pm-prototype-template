# 提交并推送

将当前工作区的全部改动提交到当前分支，并推送到远程仓库，保证远程代码与本地一致。

命令后附带的文字（如有）作为本次提交说明的补充要求。

## 执行步骤

1. 运行 `git status --short` 与 `git diff --stat`，确认当前分支、改动文件及改动规模。
2. 检查是否包含不应提交的内容：密钥、口令、令牌、`.env` 类文件、超大二进制文件。发现可疑内容时立即停止，列出文件并等待用户确认。
3. 无任何改动时，跳过提交，直接执行第 6 步核对。
4. 根据改动内容撰写中文提交说明：
   - 标题使用 `类型: 一句话说明`，类型取 `feat` / `fix` / `docs` / `style` / `refactor` / `chore`。
   - 正文用短列表概括主要改动，按业务语义描述，不罗列文件名。
5. 执行 `git add -A`、`git commit`，再执行 `git push origin 当前分支`；当前分支尚未关联远程时使用 `git push -u origin 当前分支`。
6. 运行 `git fetch origin` 与 `git status`，确认工作区干净、本地与远程一致。

## 约束

- 禁止使用 `--force`、`--force-with-lease` 等强制推送参数。
- 推送因远程有新提交被拒绝时，先停止并说明情况，由用户决定是否拉取合并，不得自行变基或覆盖。
- 不新建分支、不切换分支。

## 完成后反馈

用中文简要说明：提交编号、提交标题、推送到的分支，以及本地与远程是否一致。
